# Signal ML Guard Pipeline

This skill provides the standardized workflow for implementing, training, and integrating machine learning models as mandatory "Guards" for trading signals. This architecture ensures that mechanical signals are only executed if a model confirms the setup's statistical probability of success.

## 1. Data Extraction (Trade-Based)

Never train models on theoretical ground-truth (like perfect Savgol troughs) as they suffer from timing misalignment. ALWAYS train on actual system trades generated by running entry paths in isolation.

1. **Siloed Backtesting**: Run each entry path one-by-one with all other paths disabled.
2. **Feature Capture**: Extract the technical indicator state (normalized) on the **Signal Bar** (the bar where the signal condition was met, bar `i`).
3. **Labeling**: 
   - **Label 1 (Good)**: PnL $\ge$ 2.5% (or 4% based on study goal).
   - **Label 0 (Bad)**: Trades that hit a hard stop or momentum exhaustion.
4. **Command**:
   ```bash
   ./venv/bin/python scripts/extract_features_from_trades.py
   ```

## 2. Cost-Sensitive Training

Trading guards must be **conservative**. It is better to miss a good trade than to enter a bad one.

1. **Imbalance Handling**: Use severe class weighting (e.g., `30:1` or `20:1`) to penalize false positives.
2. **XGBoost Selection**: Prefer `XGBoost` for noisy real-world trade data as it handles non-linear indicator relationships better than simple trees.
3. **Command**:
   ```bash
   ./venv/bin/python scripts/train_ml_guard.py --dataset output/ml/dataset_trade_YYYYMMDD.csv
   ```

## 3. Model Integration (Singleton Inference)

1. **Model Storage**: Binaries MUST be versioned (`model_xgb_YYYYMMDD.joblib`) and stored in `src/trading/signals/savgol_cts/models/` for Git tracking.
2. **Singleton Pattern**: Use the `MLGuard` class in `ml_guard.py` to load the active model once into memory.
3. **Entry Check Integration**: 
   - Call `MLGuard.get_instance().score_setup(row)`.
   - Enforce a strict `min_ml_score` (typically `80.0%` for XGBoost).
   - Log the score in the rejected reason for UI transparency.

## 4. Iterative Promotion Workflow

Model drift is inevitable. Follow the weekly/monthly retraining cadence documented in [ML_ITERATIVE_TRAINING.md](references/ML_ITERATIVE_TRAINING.md).

### Workflow Summary:
1. **Extract**: Run siloed backtests to generate a fresh `dataset_trade_YYYYMMDD.csv`.
2. **Train**: Evaluate DT, RF, and XGBoost; select the winner based on **Recall for Bad Setups**.
3. **Validate**: Run `scripts/study_ml_guard_prt.py` to verify out-of-sample PnL distribution.
4. **Promote**: Update `ACTIVE_MODEL_VERSION` in `ml_guard.py` and commit the binary.

## Common Landmines

- **Temporal Misalignment**: Do not train on the "trough day" if the signal fires on the "crossover day." Features must match the state seen at inference time.
- **Edge Effects**: Always exclude the last 60 calendar days from training data to avoid Savitzky-Golay "right-edge" whipping and unrealized trades.
- **Unnormalized Features**: Never use raw price or volume in the feature set. Always use normalized metrics (e.g., `range_pos`, `velocity_norm`, `coherence`).
