# ML-Guarded Signal Integration: PRT Zero Cross

This document details the architecture and implementation of the ML-Guarded entry signal integrated into the `SavgolCTS` signal package.

## 1. Overview
The `PRT_ZERO_CROSS` entry path implements a "Model-in-the-Loop" architecture. Instead of relying solely on hardcoded technical thresholds, it uses a pre-trained XGBoost classifier as a mandatory "Guard" to evaluate the structural validity of every PRT Slope zero-cross event.

## 2. Core Modules

### `src/trading/signals/savgol_cts/ml_guard.py`
This module defines the `MLGuard` class, which operates as a **Singleton** to ensure efficient model resource management.

- **Initialization**: Loads the serialized model artifact (`src/trading/signals/savgol_cts/models/model_xgb_YYYYMMDD.joblib`) once upon first access.
- **Inference**: The `score_setup(row)` method:
    1.  Maps the input `row` (current market state) to the exact `feature_cols` expected by the model.
    2.  Handles missing values by imputing `0` (neutral state), matching training-time preprocessing.
    3.  Returns the probability score for the "Good Setup" (Label 1) class.

### `src/trading/signals/savgol_cts/entries/prt_zero_cross.py`
This module implements the entry logic, orchestrating the mechanical signal and the ML Guard.

- **Gate 1 (Mechanical)**: Verifies a positive zero-crossover of `prt_slope` (`prev_prt_slope <= 0` and `prt_slope > 0`).
- **Gate 2 (ML Guard)**: Invokes `MLGuard.get_instance().score_setup(row)` to obtain the confidence probability.
- **Threshold Enforcement**: Rejects any trade where the ML confidence (`prob_pct`) is below the configurable `min_ml_score` threshold (default `80.0%`).
- **Intensity Mapping**: The ML confidence score is passed to `compute_intensity` via `override_score`, ensuring the confidence percentage is displayed directly as the signal intensity in the UI.

## 3. Workflow Integration

### Data Pipeline
1. **Historical Silo Backtests**: All mechanical entry paths are run independently across historical data.
2. **Feature Extraction**: Indicator states are extracted on the exact bar the signal fires, and paired with the actual PnL generated by the system exits (labeling $\ge$ 2.5% swings as "Good").
3. **Cost-Sensitive Training**: An XGBoost classifier is trained with heavy class weighting (e.g., `{0: 2, 1: 1}`) to prioritize detecting failure-prone "Bad" setups, overcoming the noisiness of real-world backtest data.

### Live Inference
When the `SavgolCTSSignal` orchestrator encounters a PRT Slope crossover:
1.  The entry path performs the mechanical check.
2.  If the mechanical check passes, the `MLGuard` scores the setup.
3.  If `ML Score < threshold` (e.g., 80.0%), the entry is rejected and the reason (including the exact score) is logged for inspection.
4.  If passed, the trade enters at EOD-Lag, and exit is managed via standard CTS Trailing logic alongside system CWVAP and hard-stop guards.
